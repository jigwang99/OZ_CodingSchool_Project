# 암살자 전투 시작 도약

직업 ID 4인 유닛은 시너지 활성 여부와 관계없이 전투 시작 시 한 번 후방 도약.
언데드 그림자·오크 추적자와 적·보스에 동일 규칙 적용. 새 컴포넌트나 씬 오브젝트 배치 불필요.

- `AssassinEntryPlanner`: 시작 배치를 기준으로 대상과 착지 칸 선택. 아군은 적의 오른쪽, 적군은 아군의 왼쪽을 후방으로 판정. 월드 X 투영 → 역할 → 인스턴스 ID 순서로 생존 적 선택.
- 대상과 육각 거리가 가장 가까운 빈칸 우선. 같은 거리에서는 후방 투영 → Offset 열 → 행 순서. 인접 빈칸이 없으면 더 먼 빈칸 사용. 빈칸이 없으면 원위치에서 일반 행동 시작.
- `CombatBoard.TryReserveJump`: 비인접 도약 예약. 일반 이동의 인접 제한 유지. 점유·예약 중인 칸에는 착지 불가. 출발 칸은 착지까지 점유 유지.
- `AutoBattleController`: 양 팀을 통합한 인스턴스 ID 순서로 모든 목적지를 먼저 예약한 뒤 동시에 도약. 모두 착지하거나 중단된 다음 기존 행동트리 실행. 시작 스킬·기본 공격보다 도약 우선. 전투 제한 시간에 도약 시간 포함.
- `UnitMove.JumpToCellAsync`: UniTask 기반 포물선 이동. 기본 시간 0.35초, 높이는 셀 크기의 0.8배. UnitMove의 Inspector에서 변경 가능. 도약 중 `IsMoving`과 `IsJumping`으로 공격·스킬 차단. 일반 이동과 동일한 방향 이벤트 사용.
- 기절·사망·취소 시 출발 칸으로 복귀하고 목적지 예약 해제. 준비 배치는 변경하지 않음. 새 준비 단계·풀 재사용 후 도약 상태를 유지하지 않음. 이전 비동기 작업이 다음 사용의 위치·이동 상태를 변경하지 않도록 작업 소유권과 유닛 수명 확인.

현재 PIXEM 이동 애니메이션과 포물선 좌표를 사용. 전용 도약 애니메이션·잔상·착지 이펙트는 별도 에셋 연결 범위.
시트 열과 JSON 스키마 변경 없음.

`PixelTactics > Checks > Run Assassin Entry Checks`에서 대상 동률·양 팀 방향·예약 충돌·빈칸 부족·실제 포물선·행동 잠금·취소·기절·사망·풀 재사용 검사. 기존 전체 Play 검사에도 포함.
